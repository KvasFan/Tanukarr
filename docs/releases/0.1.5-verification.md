# Tanukarr 0.1.5 verification ledger

This ledger records the checks run on November 2 and 3, 2026 for the 0.1.5
source. Hosted evidence for the release tag belongs in the 0.1.5 publication
report.

## Application code

The release commit changes no application source. The application code is that
of `main` commit `651f8f4ab`. Compared with 0.1.4, it adds three commits:

- `ef49eac6a` adapts upstream Sonarr's `3b21b27d2`: series ID in series
  addresses and non-unique title slugs, as migration 254;
- `d629067b2` moves a grouped-series test to the remaining unique TVDB ID index;
- `651f8f4ab` adds credits.

### Local checks

The checks ran in the same disposable containers as for 0.1.4:

- `mcr.microsoft.com/dotnet/sdk:10.0.402`;
- `node:24-bookworm`, on a clean copy of the tracked files.

Both containers were restricted to IPv4.

| Check | Result |
| --- | --- |
| `dotnet build src/Sonarr.sln -c Debug` | Succeeded |
| Core (`TestCategory!=IntegrationTest`) | **7,947 passed**, 27 skipped, 0 failed. This is two fewer tests than for 0.1.4: the four tests of the deleted slug validator were removed, and a migration test and a shared-slug test were added |
| API | **352 passed** on the series-ID tree. The later commit `d629067b2` changes only a Core test |
| Frontend | TypeScript, ESLint, Stylelint, **222 node tests** and the Vite build all succeeded |

The Common, Host and HTTP suites were not rerun for this change: none of their
code or tests changed.

Verification found two failures, and both were fixed before pushing:

- **The `AddGroupedSeriesPersistenceFixture` test of an unrelated unique
  violation failed.** It provoked that violation through a duplicate slug, and
  slugs are no longer unique. The test now provokes it with a duplicate TVDB ID
  and gives the second series a separate path. A new test stores two members
  that share a title slug.
- **The redirect from a slug-only address dropped the `#season-N` fragment.** The
  redirect now keeps both `?season=` and the fragment.

### New regression coverage

- `254_series_title_slug_not_uniqueFixture`: after the migration, two series can
  be stored with the same slug.
- `AddGroupedSeriesPersistenceFixture.should_store_members_that_share_a_title_slug`.
- `frontend/tests/collections.test.cjs` and `animeGrouping.test.cjs`: collection,
  season and member links use `/series/<slug>/<id>` and keep `?season=` and
  `#season-N`.
- `docker/tests/collections-browser.cjs`, in the packaged browser gate:
  - checks the new link targets and the page path;
  - checks that a slug-only address with a season fragment redirects to the ID
    address and keeps the fragment.
- `docker/tests/ui-jellyfin-watched.cjs` waits for the ID address.

## Release preparation

The release commit does the following:

- sets `VERSION` and the Dockerfile default to 0.1.5;
- adds these release notes;
- updates the README, FORK, CONTRIBUTING, the Docker guide, the documentation
  index and CONTRIBUTORS.

It changes no application source. The tag run executes the light gate profile.
The publication report records its result, the public digest and the assets.

## Not run

- No local Docker image was built.
- The container fixtures (browser, provider, download and upgrade gates) run only
  in the hosted workflow.
- The ID addresses were not tried on a real library in a browser outside the
  hosted fixtures.
