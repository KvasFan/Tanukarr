# SonarrWeeb 0.0.1 verification

This report describes the independently versioned SonarrWeeb release **0.0.1**.
Its compatible internal Sonarr assembly/API version remains `10.0.0.*`.
The v3 and v5 status APIs and frontend initialization expose the separate
`productName` and `productVersion` fields.

## Final upstream snapshot

The release contains upstream Sonarr `develop` at
[`57816c149`](https://github.com/Sonarr/Sonarr/commit/57816c149d02f95543973fefb4780c4495f8121c),
verified on October 12, 2026. Five commits arrived after the previous
`59c22e859` checkpoint while release preparation was running. The final update
includes the development HTML-loading fix and regenerated v3 API documentation,
with Mark McDowall's original commits preserved. The fork retains its own CI,
release configuration and AI contribution policy.

## Container and release verification

The Docker release workflow builds Linux AMD64, runs frontend and backend checks,
then runs isolated container smoke and functional/security checks before
publishing the exact tested image. The smoke checks verify product metadata in
both API versions and frontend initialization.

Release packaging checks the committed source revision, OCI labels, image
platform, Docker archive configuration and layer identity, passing test reports,
and a nonempty CycloneDX inventory. The published bundle includes the Docker
archive, corresponding source archive, Compose YAML, SBOM, verification reports,
release manifest and SHA256 checksums. Read those reports for the actual image
ID and execution scope; an SBOM inventories dependencies and does not establish
that they are free of vulnerabilities.

The workflow actions are pinned to verified commit IDs. Workflow YAML and shell
expressions passed actionlint, YAML passed a parser with duplicate-key rejection,
and the packager passed Python compilation and actual Docker 29 archive checks,
including rejection of mismatched identity, labels and filesystem layers.

The complete Linux suite checkpoint at `680d49a85` passed **7,076 tests**:
Core 6,122; API 56; HTTP 57; Common 754; Host 17; Update 17; Libraries 2;
Mono 51. Console skips were 27, 42, 4 and 5 in Core, Common, Host and Mono;
TRX also records platform outcomes excluded from those console counts.
The image build passed with six recovered MSB3026 copy-retry warnings.

The first GitHub functional run caught a harness error in the new product
metadata check: it requested the UI-only `/initialize.json` with an API key
instead of a Forms cookie. Authentication correctly denied that request. The
harness now uses its authenticated cookie only for UI initialization, continues
using API keys for API routes, and checks that anonymous/API-key-only UI
initialization cannot expose credentials. All **16 offline functional checks**
passed on the initial image after this correction. The failed report and log
are retained; application authentication was not weakened.

The added GitHub Actions scan identified inherited mutable action references and
inline shell interpolation. All **17 inherited external action uses** are now
pinned to verified commits, and composite inputs are passed through quoted
environment variables with newline/path/version checks. Verification passed
**29 extracted-script cases**, 36 Bash syntax checks and an explicit scan of
eight YAML files with **zero GitHub Actions rule findings or parser errors**.

## Security limitations and attribution

The inherited audit records unresolved ImageSharp, Ubuntu and build-only
dependency findings. See the
[security and functional audit](../security-functional-validation-2026-10-12.md)
for findings, mitigations and limits. Do not interpret a successful build or
functional test as a clean cybersecurity assessment.

Tests use disposable instances and generated data. They do not establish that a
real library, real download client, private AniList account or VAAPI hardware has
been exercised. AniList membership status, anime release status and custom-list
membership remain distinct; see [Library tools](../library-tools.md).

The complete source and feature credits are in
[CONTRIBUTORS.md](../../CONTRIBUTORS.md). This integration and release preparation
used **OpenAI Codex based on GPT-6**. Historical Claude and Codex model labels are
preserved as recorded source declarations; unknown model identities are not
invented.
