# Tanukarr 0.1.5 publication

The hosted workflow published the **linux/amd64** release on November 3, 2026
(00:04 UTC). The release was checked independently on the same day.

- The [GitHub release](https://github.com/KvasFan/Tanukarr/releases/tag/v0.1.5) is
  the repository's latest release and carries nine assets.
- The source is commit [`ca92fe835`](https://github.com/KvasFan/Tanukarr/commit/ca92fe835b0c56b68c19c0eaedc0087a941248d8).
- The annotated `v0.1.5` tag resolves to that commit.

**Not done: the GitLab mirror.** The maintainer publishes it to
[gitlab.com/tirael8308/Tanukarr](https://gitlab.com/tirael8308/Tanukarr); see
*Remaining work*.

## Hosted runs

The release commit and the `[skip ci]` ledger commit after it were pushed
together. That push started no run on `main`; the tag push started the only
release run.

| Run | Result |
| --- | --- |
| [Docker and Release 41548310979](https://github.com/KvasFan/Tanukarr/actions/runs/41548310979) (`v0.1.5`) | **Light gate profile**: success in 15 minutes, 98 checks. The image publication, SBOM, packaging and release publication also succeeded |
| [Docker and Release 41486456072](https://github.com/KvasFan/Tanukarr/actions/runs/41486456072) (`main`, `651f8f4ab`) | Full gate profile on the same application code: success |
| [CI 41486456075](https://github.com/KvasFan/Tanukarr/actions/runs/41486456075) (`main`, `651f8f4ab`) | Success: backend build and test suites, frontend lint and build |

The light-profile run covered these gates:

- the image build with every in-image suite;
- smoke (12 checks);
- functional/security (19);
- quality/codec (22);
- custom qualities (28);
- first run (4);
- the populated-library upgrade to schema 254 (13).

## Local checks of the published image

A disposable container was started from the `0.1.5` image pulled from the
registry. It had no configuration and was removed afterwards.

| Check | Result |
| --- | --- |
| Startup | `/ping` answered |
| `GET /api/v3/system/status` | `migrationVersion` 254, runtime `10.0.13` |
| `GET /series/some-slug/42` without a session | Redirected to `/login?returnUrl=%2Fseries%2Fsome-slug%2F42`, so the ID address is kept through login |

These checks did not use a browser session, a real library, an indexer or a
download client with the published image. The ID addresses, the redirect from
slug-only addresses and the shared slugs were checked by:

- the hosted full-profile browser gate on `main`;
- the Core and frontend tests.

## Security and remaining work

- No new vulnerability scan of the public image was recorded for 0.1.5. The
  [0.1.0 inventory](0.1.0-image-security.json) is still the latest scan run, so
  this release must not be described as vulnerability-free.
- The tag ran the light gate profile. The browser, provider/list, Jellyfin and
  genuine-download gates ran in the full profile on `main` (run 41486456072), on
  the same application code but not on the tagged commit.
- **The GitLab mirror is pending.** The maintainer will do the following with
  their own credentials:
  - push `main` and `v0.1.5`;
  - push the image to `registry.gitlab.com/tirael8308/tanukarr` (`0.1.5`, `latest`);
  - upload the nine assets to the generic package `tanukarr`/`0.1.5`;
  - create the `v0.1.5` release entry.
