# Tanukarr 0.1.0 maintenance verification

This ledger covers native movie catalogues, mixed collection compatibility and
dependency/container hardening after source `74400056`. It records executed
checks only. The [initial publication report](0.1.0-publication-initial.md)
and [preparation ledger](0.1.0-verification.md) retain their original source
checkpoints; their counts do not verify this work.

## Backup and scope

Before implementation, all nine published assets were downloaded and their
sizes/SHA-256 digests checked against GitHub metadata. A complete Git bundle was
verified. Two briefly paused local containers received consistent configuration
snapshots, including SQLite WAL files; restored copies returned `ok` from
`PRAGMA integrity_check`. Private configuration backups remain local.

Application tests use disposable configurations, generated media, owned HTTPS
catalogue fixtures and actual local qBittorrent/Jellyfin servers. No owner
library is downloaded into, renamed, moved, rescanned or upgraded by these
tests. No live TMDB/OMDb API credentials were supplied. Provider contract tests
exercise real HTTP JSON deserialization, not hand-constructed resource objects;
they do not establish live-account coverage or current catalogue accuracy.

## Preparation checkpoints

- The twelfth Windows solution Debug build passed with zero warnings/errors.
  On that checkpoint, Core passed 7,810 cases (19 skipped), API 330, HTTP 80,
  Host 36 and selected Common security regressions 103. Genuine PostgreSQL 17
  passed 28 persisted migration/range/concurrency cases. Focused reruns are not
  added to these totals.
- Frontend passed 198 tests, ESLint, Stylelint, TypeScript and the Vite build.
  Lazy routes and a complete timezone-data asset remove the large-chunk warning
  without truncating historical timezone rules. Browser verification is separate.
- A baseline pack fixture on immutable source `90d18969` passed 21 checks:
  three real torrents, four explicit grabs, 315,056,928 transferred bytes and
  four observed selected-library Jellyfin refresh events. It verifies the
  existing TV transport and the fixture, not the new movie implementation.

## Defects found while verifying

- Strict new movie parsing initially rejected established AniList/MyAnimeList
  `S01E01` files. Source-gated native matching and retained persisted/explicit
  file mappings preserve those imports without relaxing ordinary movie matching.
- Generic TV parsing interpreted a title/year film as season 20, episode 19,
  while a native film could accept TV coordinates. Movie ownership now selects
  the strict movie parser before TV mapping; TV parsing remains unchanged.
- The season-search modal's saved TV pack filter hid unnumbered film releases.
  Movie/special searches now use a local All filter while preserving TV policy.
- The new movie naming override changed established AniList/MyAnimeList import
  filenames despite a configured anime format. Actual group/client fixtures
  reproduced it. Movie Format is now scoped to TMDB Movies/OMDb, retaining native
  anime film formatting as well as existing file identity.
- Complete-series grab validation accepted only TV season coverage. An actual
  same-collection film pack appeared in search but its explicit v5 grab returned
  HTTP400. Both API versions now validate native single-film and current saved
  collection-pack contexts separately, preserving the existing TV guard.
- The following real transfer exposed a second pack defect: the grab retained
  only its anchor film's native episode ID, so another physical film was rejected
  and the anchor import prematurely completed the pack. Recovered movie context
  now validates the saved grab, current monitored collection, unique physical
  title/year identity and native feature IDs. Pack completion requires readable
  files for the verified members; unrelated or rejected files cannot disappear
  behind a successful anchor import. Final-image transfer verification is
  recorded separately from focused regressions.
- ConfigService Trace logged raw configuration/default values. Tests now verify
  that TMDB/OMDb keys and generated salts persist correctly without appearing
  in setting-write/default diagnostics.
- Raw Trace fixture inspection then found a separate console leak: unofficial
  assembly versions bypassed the existing URL cleanser. Standard and CLEF
  console layouts now cleanse credentials regardless of release classification,
  while retaining ordinary diagnostics and valid structured JSON.
- Naming editors emitted unknown-codec warnings from stale built-in `AVC`
  sample metadata. Native `h264` samples keep the real naming path without
  changing the shared codec formatter or suppressing its diagnostics.
- Actual Library Import and notification-editor probes exposed an uninitialized
  search string, premature Jellyfin options requests, a missing English key and
  overlapping touch checkbox labels. The search initializes safely, dependent
  options require a valid connection, and the labels retain readable alignment.
- Vite's emitted JSON/fonts initially used an unsupported static asset route.
  Packaging below the existing Content route fixed actual post-login boot errors.
  An independent candidate2 nested-base browser probe passed; an additional
  suspected URL-base problem was not reproduced and did not prompt a code change.
- A full fresh Linux dependency install exposed disabled-script warnings absent
  from an already prepared workspace. Reviewed nonessential hooks are explicitly
  disabled; native resolver/watcher packages are actually loaded during build.
- Intermediate failures in generated media fixtures were retained: undersized
  and audio-free files were correctly rejected, a scheduler freeze prevented
  interval refresh, and an unrequested season was intentionally left in its
  downloaded pack. Fixtures now generate acceptable media, run the real refresh
  scheduler and explicitly grab the retained season before expecting its import.
  A later Library Import fixture also lacked an audio stream and was correctly
  rejected; generated AAC was added instead of weakening import validation.

## Security decisions and limits

The production ImageSharp consumer and advisory suppressions were replaced by
SkiaSharp. The application has a silent local health probe and ships no
setuid/setgid helpers. Startup still prepares the configured nonroot account and
then drops privileges; the Docker root-startup lint finding remains intentional
for that ownership contract. It is not hidden with a suppression or misleading
`USER` declaration.

The maintained project-scoped Yarn, ESLint, Stylelint and updated action runtimes
remove obsolete tooling. One unpatched high-severity `braces` advisory remains
in build-only dependencies
([GHSA-vfj7-8cjw-p6xm](https://github.com/advisories/GHSA-vfj7-8cjw-p6xm),
with no published patched version at the October 15 check). It is not shipped
in the application runtime image.
The runtime inventory and exact-image scan results belong in the
[publication report](0.1.0-publication.md) once verified. No vulnerability-free
claim is made.

The existing Noble base was compared with an official Resolute alternative
using the same current Trivy database. The alternative increased findings and
was not adopted. Core/transitive NuGet auditing completed with no reported
vulnerable packages; the whole-solution listing encountered an unrestored
Windows-only GUI project and is not reported as a successful complete audit.

Roles followed pinned [wshobson/agents definitions](https://github.com/wshobson/agents/tree/044b4b21f083948e69ec878a7b07c8d0951a6ffa).
