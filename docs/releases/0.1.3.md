# Tanukarr 0.1.3

Tanukarr **0.1.3** fixes defects reported from the library and Settings →
Quality screens of a 0.1.2 installation with a large library. It keeps the
inherited database schema (253), the v3/v5 APIs, provider identities and every
0.1.2 feature. Back up the configuration before upgrading; use a compatible
configuration backup when restoring an older image.

## Changes

- **Library collection covers.** Collection cards in the library poster and
  overview views now load their covers as soon as they appear. Previously the
  cards mounted while scrolling the virtualized grid kept the Tanuki
  placeholder, while native series cards showed their posters.
- **Collection search progress.** Search Collection shows a spinner while it
  runs, counts the entry being searched ("Searching 1 of 2 entries…") and
  labels each entry as searching, waiting, failed or with its release count.
  Before, it showed "Searching 0 of N entries…" and nothing else for the whole
  search.
- **Quality page saves.** Saving Quality Definitions sizes publishes one
  profile-batch event instead of one event per quality profile. Each event
  re-maps every pending release, so on a library with about 3,800 pending
  releases a save took about 17 seconds and now takes about 3.
- **Edits during a save.** Values edited on the Quality page while a save is
  still in progress are kept and sent by the next save instead of being
  discarded. A second Save (including Ctrl+S) is ignored while one is running.
- **Release workflow.** Release tags run a lighter set of hosted gates on code
  that already passed the full set on `main`; the fixtures' database checks no
  longer fail intermittently on hosted runners; every fixture's container log
  is kept with the hosted reports. See *Verification* below.

## Upgrade

Pull `ghcr.io/kvasfan/tanukarr:0.1.3` and recreate the container. No database
migration beyond schema 253 runs; 0.1.0, 0.1.1 and 0.1.2 configurations start
directly.

## Installation and verification

Use the [Docker installation guide](../docker-installation.md). The published
image is `ghcr.io/kvasfan/tanukarr:0.1.3`; `latest` selects the tested release.

The application code of this release is identical to `main` commit
`7e669cbbb`, whose hosted
[Docker and Release run 39110439743](https://github.com/KvasFan/Tanukarr/actions/runs/39110439743)
passed the full gate profile (every fixture, including the browser, provider
and genuine download gates). The release commit adds only the version number,
documentation and the workflow's gate profiles. The tag run then executes the
**light** profile: the image build with every in-image test suite, smoke,
functional/security, first run, quality/codec decisions, custom qualities and
the populated-library upgrade from the earlier release; `release-manifest.json`
records `gateProfile: light`.

The [verification ledger](0.1.3-verification.md) and the
[October 18 ledger](../local-deployment-verification-2026-10-18.md) record the
executed checks, including the reproduction on a disposable copy of the
reporting library. This release must not be described as vulnerability-free;
the 0.1.0 security inventory remains the latest recorded public-image scan.
