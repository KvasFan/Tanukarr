# Tanukarr 0.1.1 publication

The **linux/amd64** release was published by the hosted workflow and
independently checked on October 17, 2026. The
[GitHub release](https://github.com/KvasExpert/Tanukarr/releases/tag/v0.1.1)
is the repository's latest release and carries nine verified assets. Its source
is [`2ea71400`](https://github.com/KvasExpert/Tanukarr/commit/2ea71400bce9e97201b1b3492cf0553eb67a8019);
the annotated `v0.1.1` tag resolves to that commit.

[Source CI 39038136664](https://github.com/KvasExpert/Tanukarr/actions/runs/39038136664)
(backend build and suites, genuine PostgreSQL, FFmpeg worker; frontend lint and
build) and the
[tag verification and publication run 39038153178](https://github.com/KvasExpert/Tanukarr/actions/runs/39038153178)
(verify and publish 60 minutes, release publication) both succeeded. The
`edge` run for the same `main` commit
([39038136681](https://github.com/KvasExpert/Tanukarr/actions/runs/39038136681))
failed once in its SIMKL fixture with the SQLite error `GET /api/v5/command:
attempt to write a readonly database` after ten passing checks; the identical
fixture passed on the tag run of the same source and locally, so the failed job
was rerun. The rerun result is recorded below when known; it does not change
the published release.

## Local deployment

The local `sonarr-pro` Compose service was recreated from the digest-pinned
published image (`sha256:2d47ba87…`, tagged locally as `tanukarr:local`) on
the existing `./config`, after the day's earlier configuration backup. The
container reported healthy within 25 seconds; the startup log shows
`Starting Tanukarr 0.1.1`, only the engine-version check migrations (schema
stays 253) and the expected Kestrel port-override warning, with zero error or
fatal lines. Through the API the instance keeps its 292 series and reloaded
its 246 non-fallback pending releases, Forms authentication stays enforced
(anonymous requests redirect to `/login`, missing keys receive 401), and
health reports only the owner's missing download client and empty root folder.

## Security and remaining findings

No new public-image vulnerability scan was recorded for 0.1.1; the
[0.1.0 inventory](0.1.0-image-security.json) remains the latest executed scan
and this release must not be described as vulnerability-free. The build-only
`braces` advisory and the DS-0002 configuration finding described for 0.1.0
are unchanged.
