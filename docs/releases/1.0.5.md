# Tanukarr 1.0.5

**Published and deployed.** All three hosted workflows passed on the release
source. The public image, nine assets, fourteen runtime reports (251 checks) and
protected owner upgrade were verified. See the
[publication follow-up](1.0.5-publication.md) for exact evidence and remaining
dependency findings. The [verification ledger](1.0.5-verification.md) preserves
the earlier candidate states, local test scope and failures.

Local preparation passes 7,998 executed native tests, 115 frontend tests, the
29-test Linux compression worker, fourteen runtime reports totaling 251 checks,
and four actual preference browser checks. Those scopes overlap where explained
in the ledger and do not establish private external-account or owner-library
execution. Dependency findings remain; the image scan reports no Critical CVEs
but includes High findings.

This release adds complete import-scoped list snapshots, local
filtering and duplicate-read reuse where provider APIs support them. AniList's
full account collection also provides direct public relations to reduce repeated
grouping requests. Private temporary snapshots are released after import/Test;
required saved membership and SIMKL's restricted incremental baseline remain.

Two saved definitions can share a complete provider/account/grant/request read
during one operation while keeping independent local selections. The next
synchronization fetches a fresh snapshot. AniList starts with all selected-user
anime collection groups, including custom-only entries, instead of filtered
status pages plus membership recovery. Valid nullable ancillary fields are
accepted; missing identities, conflicting entries and incomplete chunks still
retain the previous successful list. Provider capabilities and limits differ;
the [provider matrix](../library-tools.md#provider-capabilities) describes them.

**Metadata provider for new series** offers Automatic, TheTVDB, TMDB, AniList and
MyAnimeList/Jikan on every import-list definition. A preference is used only when
the item supplies that catalogue's positive ID. An unavailable preference falls
back to the existing Automatic order: TheTVDB, AniList, TMDB, then MyAnimeList.
This creates no guessed cross-catalogue mappings or extra identity lookups.
The manual Add New Series provider choice remains available.

Existing source ownership, numbering and paths remain unchanged. Changing the
preference affects future additions. Native catalogue IDs never become TVDB
IDs; AniList/MAL additions can still need a unique negative internal TVDB slot.
Addition logs now show the native provider/ID and the internal placeholder
separately, after metadata preparation. They do not claim that a title is absent
from TheTVDB without a verified mapping. Existing native import exclusions are
retained when a different supplied catalogue is selected.

Migration **250** adds only `ImportLists.PreferredMetadataSource`, defaulting to
Automatic. V3/V5 return the preference, reject unknown enum values and preserve
a saved preference when an older client omits the field. Explicit Automatic
resets it. API v3 and v5 remain supported; no API v4 is added.

Read [complete list snapshots and provider identity](../import-list-snapshots.md)
for supported providers, payload limits, filtering semantics and the distinction
between local API requests, external metadata and software licensing.

The release continues the 1.0.4 Jellyfin watched/progress and successful manual
backup features. Additional Jellyfin NFO/artwork output and a server metadata
reader are paused work and are not included in 1.0.5. Documentation is maintained
in English under
**KvasExpert/Tanukarr**, with original contributor attribution and the actual
local tool/model identity: **OpenAI Codex, based on GPT-6**.
