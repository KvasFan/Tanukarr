The [upstream audit](../upstream-audit-2026-10-13.md) is a source compatibility
review. The [quality/codec guide](../quality-and-codec-size.md) describes the
implementation contract; it does not establish an encoder-efficiency benchmark
or measured visual quality. Existing release/source facts in the
[1.0.2 verification](1.0.2-verification.md) and
[publication follow-up](1.0.2-publication.md) remain scoped to that checkpoint.

The first two native build attempts failed with nine namespace/unused-import
errors and one remaining unused import respectively; both were corrected.
An initial 155-case Core run had five mixed-metadata failures against output
compiled before the last source edit. The solution was frozen and rebuilt, and
the fresh focused run passed all 155. A later focused run including one
additional case passed all 156. The passing frozen build and fresh test
results are the authoritative source checkpoint, not the earlier outputs.
Failed build receipts remain in `build-first.log` and `build-second.log`.
The initial Core log was overwritten by a later run; its preserved
`native-first-core-output-excerpt.txt` is a transcript excerpt, not the complete
original log. Current native receipts include `build-native-catalog-guard.log`,
`core-focused.log` and `api-all-catalog-guard.log` in the release artifact root.

The first frontend typecheck reported five errors from a flag placed in the
wrong interface. Moving the field corrected the typing and the full gates then
passed. The first Docker candidate failed at the UI stage because the native
test fixture's English resource was missing from its build context. The
Dockerfile was corrected to copy the actual resource. The second candidate
assembled successfully and passed 7,245 Core, 226 API, 57 HTTP and 101 selected
Common tests (7,629 passed; 27 Core tests ignored). Later API/UI corrections
require a fresh final-source build; these candidate counts are not substituted
for its verification.

The first packaged browser setup encountered the expected production Swagger
404. Generated Swagger is exposed only in Debug builds; the fixture now records
that scope and continues with the production UI. A second browser attempt passed
login and hourly display, then caught global JSON camel-casing of human codec
dictionary keys. The API now uses explicit dictionary serialization options;
native tests check canonical labels and factors. An intermediate guard build
also reported six indentation errors, corrected before the fresh 234-case API
pass. Both browser attempts cleaned their owned configurations. Their reports
remain separate from the required passing final-image browser run.

The next browser run correctly displayed Unlimited, but its comparison expected
explicit null leaf fields where inherited MVC profile GET serialization omits
them. The fixture now normalizes only absent `minSize`, `preferredSize` and
`maxSize` read properties to null. Numeric values and every other profile field
remain strictly compared; write omission still preserves values and explicit
null still clears a selected limit. Production serialization was not changed.

The API/RSS fixture also exposed an inherited bulk-body validation failure:
a null resource inside an update array produced HTTP 500 before the quality
service could reject it. The shared REST controller was unchanged from upstream
before this correction. It now rejects null resources with HTTP 400; the fresh
HTTP suite includes ten corresponding guards. This is separate from nullable
size-property handling and does not convert invalid requests into successful
updates.

An independent actual Chromium run against immutable candidate
`sha256:a0a2589e1662d41bb35bce1fbf66cdc36683e0933560fbcc6564912d886b95b3`

## Evidence location and limits

Ignored local receipts for this work are under
`_artifacts/release-1.0.3-2026-10-13`. The `upstream-audit` directory currently
contains the public GitHub responses, sequential fetch logs, author records,
comparison results and old proposal patches. Other receipts will be recorded
only after their corresponding checks actually run. A normal clone does not
include these local artifacts.

Failed attempts must remain identifiable rather than being overwritten as a
passing run. A mock provider proves the exercised API contract under controlled
responses, not external uptime or a real private-account import. A successful
Jellyfin refresh request does not by itself establish completion of its
asynchronous scan. A public image digest must be verified separately from the
local build ID before publication is claimed.
