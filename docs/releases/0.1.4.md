# Tanukarr 0.1.4

Tanukarr **0.1.4** fixes the collection search for anime collections, makes the
codec size factors editable on the Quality page, brings back the quality-limit
sliders and imports fixes from upstream Sonarr and the fork sources. It keeps the
inherited database schema (253), the v3/v5 APIs, provider identities and every
0.1.3 feature. Back up the configuration before upgrading, and use a compatible
configuration backup when restoring an older image.

## Changes

### Collections and search

- **Collection search finds collection-numbered releases.** Search Collection
  searched each member only by its own title. An anime collection member such as
  "Assassination Classroom Second Season" is often released under the collection
  title with the collection's season number, for example
  `Assassination Classroom S02 …` or `… (2015) - Season 2 (S02)`. Complete-series
  searches of a collection season member now query the collection title with the
  member's collection season on Nyaa, Newznab/Torznab and text indexers. The
  parser maps that season back to the member. A collection title never matches
  another member's season, the whole collection, an absolute episode range or a
  year after the member's own year.
- **Bare single-season batches.** Single-season series accept packs named only by
  the title followed by quality or audio tokens, such as
  `[Group] Title [Dual Audio]` or `Title (BD 1080p HEVC)`. This is adapted from
  ikatun's fork. Automatic searches of single-season series now try the
  complete-series pack first.
- **"Title (Year) - Season N"** is recognised; the dash after the year no longer
  hides the season.
- **Air dates moved into the past.** Monitored episodes whose air date moves from
  the future, or from unknown, to the last 14 days are searched after a refresh.
  An example is a season listed weekly and then released all at once (from ikatun).

### Settings → Quality

- **Editable codec factors.** The codec size table is editable. Saving applies only
  the edited codec family to every quality profile, and each profile can still
  override it in the profile editor. A factor that differs between profiles is
  shown as *Mixed*. New endpoints: `GET`/`PUT /api/v3|v5/qualitydefinition/codecfactors`.
- **Quality-limit sliders.** Each quality definition has the minimum, preferred and
  maximum range slider again, next to the hourly fields. Dragging one thumb edits
  only that limit, so limits that differ between profiles stay untouched.

### Queue, library and maintenance fixes

- **Ignore download** no longer removes the download from the client (upstream).
  The v5 queue removal endpoints take `removalMethod` and `blocklistMethod`.
- Bulk-removing two pending releases for the same episodes no longer fails with a
  server error (from gaboy498-byte).
- Renaming a series moves extra files only for the episode files that were
  actually renamed (from gaboy498-byte).
- Upstream fixes:
  - automatic tags on full refresh;
  - database restore validated, with the previous database kept until the restore
    succeeds;
  - expired cache entries;
  - wildcard Allowed Hosts;
  - authentication responses not cached;
  - pushed releases with an unknown indexer name;
  - average file size;
  - release profile deletion;
  - custom format import and score saving;
  - Manual Import release group;
  - iCal all-day events;
  - queue status count;
  - missing/cutoff lists after monitoring changes;
  - unmonitoring under an unmonitored series;
  - command body deserialization;
  - missing episode files;
  - API version header;
  - bulk tag removal;
  - episode file details from History/Queue;
  - long log message cleansing with regex timeouts.
- Logs keep being cleansed in every build, and the fork's broader `api_key` rules
  are kept.

## Upgrade

Pull `ghcr.io/kvasfan/tanukarr:0.1.4` and recreate the container. No database
migration beyond schema 253 runs; 0.1.0 to 0.1.3 configurations start directly.

External callers of the **v5** queue `DELETE` endpoints must send
`removalMethod` (`removeFromClient`, `changeCategory` or `ignore`) and
`blocklistMethod` (`doNotBlocklist`, `blocklistAndSearch` or `blocklistOnly`)
instead of `removeFromClient`/`blocklist`/`skipRedownload`/`changeCategory`.
This follows upstream Sonarr. The v3 API is unchanged.

## Installation and verification

Use the [Docker installation guide](../docker-installation.md). The published
image is `ghcr.io/kvasfan/tanukarr:0.1.4`; `latest` selects the tested release.

The release follows the 0.1.3 procedure. The application code passed the full
gate profile on `main`, and the tag runs the light profile. The
[verification ledger](0.1.4-verification.md) records the executed local and
hosted checks. This release must not be described as vulnerability-free; the
0.1.0 security inventory remains the latest recorded public-image scan.
