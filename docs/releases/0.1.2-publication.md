# Tanukarr 0.1.2 publication

The **linux/amd64** release was published by the hosted workflow in the new
`KvasFan/Tanukarr` repository on October 17, 2026 and independently checked
the same day. The [GitHub release](https://github.com/KvasFan/Tanukarr/releases/tag/v0.1.2)
is the repository's latest release and carries nine verified assets; the same
assets, image and release entry were mirrored to
[GitLab](https://gitlab.com/tirael8308/Tanukarr/-/releases/v0.1.2). The source
is [`a62c4543`](https://github.com/KvasFan/Tanukarr/commit/a62c4543852daebdc9f57fe2941076739d5f2e42);
the annotated `v0.1.2` tag resolves to that commit on both hosts.

## Hosted runs

Before the tag run, the earlier 0.1.0 image (schema 252) was re-published from
the local Docker store to `ghcr.io/kvasfan/tanukarr:0.1.0` and
`registry.gitlab.com/tirael8308/tanukarr:0.1.0`; both pushes reproduced the
original digest `sha256:74b13c7a6fd59222a498cb8bbb14be149a2d505846d684a8aa2e78de280dd9bd`
that the workflow and the upgrade fixture reference, and both are pullable
anonymously. GHCR rejects the gh CLI's OAuth token and fine-grained personal
access tokens; the push used the OAuth token only after a Windows pipe
artefact (a UTF-8 BOM prepended to the piped secret) was removed by passing
the token through a transient file.

## Local deployment

The local `sonarr-pro` Compose service was recreated from the digest-pinned
GitHub image; it reported healthy, logged `Starting Tanukarr 0.1.2`, kept
schema 253, its 292 series and Forms authentication.

## Security and remaining findings

No new public-image vulnerability scan was recorded for 0.1.2; the
[0.1.0 inventory](0.1.0-image-security.json) remains the latest executed scan
and this release must not be described as vulnerability-free. The previous
namespace's releases and images remain unreachable while that account is
suspended.
