# Tanukarr 1.0.0

Tanukarr 1.0.0 manages **TV series and anime** with shared library, search,
download-client and import workflows, plus a metadata provider selected per
title. It continues the earlier releases, with the supplied
Tanuki logos and the integrated Sonarr Pro features preserved. This release
includes the shared AniList request-limit fix and corrected Nyaa search encoding
added after the immutable historical 0.1.0 release.

## Install or upgrade

Follow the [Docker installation guide](https://github.com/KvasExpert/Tanukarr/blob/v1.0.0/docs/docker-installation.md) for complete
Compose YAML, anonymous GHCR pulls, storage, permissions, authentication and
offline image loading. The new standalone release YAML uses `TANUKARR_*`
variables and maps loopback host port 6970 to container port 8989.

Existing Tanukarr users should change the image to
`ghcr.io/kvasexert/tanukarr:1.0.0` while keeping their original configuration
mount, media mounts and Compose project/volume identity. Take a consistent
backup first. Changing `<existing-config-volume>` to a new `tanukarr-config` volume
starts an empty instance; the rename does not migrate storage automatically.
The checked-in local Compose retains the recorded environment aliases for compatibility.

**1.0.0 is the product version.** The inherited Sonarr core remains
`10.0.0.*`. Sonarr executable/assembly names, `config.xml`, `sonarr.db`, database
migrations and API-key authentication remain compatible with the fork.
**API v3 and v5 are supported; API v4 is not implemented.** See
[compatibility and backups](https://github.com/KvasExpert/Tanukarr/blob/v1.0.0/docs/compatibility-and-backups.md).

The General-settings default Instance Name is `Tanukarr`. Names saved through
the UI/API must start or end with `Tanukarr` or legacy `Sonarr`, preserving the
existing anchored name policy. Existing custom names are retained when read.

## Included features and fixes

- Per-series metadata selection: TheTVDB/TMDB TV catalogues, including anime
  they list, and AniList/MyAnimeList/Jikan anime catalogues. The selected entry
  retains its provider identity through refresh, matching and list workflows.
  TMDB episode groups apply to TMDB-owned titles; use Default for other owners.
  IMDb is not a fifth metadata source, and its inherited ordering choices are
  not applied by the current backend.
- Compatible KakarottoCake, gaboy498-byte and ikatun features: complete-series
  searches, pack-first acquisition, multi-season packs, guarded numbering,
  fake-release filtering, library tools and retained versions.
- Dedicated **Jellyfin** Connect integration: select one initialized library,
  refresh after each import, on a conditional interval, or both. The interval
  defaults to 60 minutes and can be reduced to 1 minute. Idle ticks make no
  refresh request; pending imports survive restarts and request failures.
- **AniList**: multiple included and excluded custom lists, six explicit
  watching-state exclusions and exclusion precedence across paginated results.
  Account-list state, anime release state and custom-list membership remain
  distinct filters; an exclusion vetoes Watching/included-list membership.
- **AniList request-limit recovery**: shared request pacing/cooldown across list
  pages, tests, searches and metadata, retry/reset header handling and bounded
  recovery from temporary HTTP 429 responses. Prolonged failures preserve the
  prior cached list rather than authorizing destructive cleanup.
- **Nyaa**: correctly encoded search titles containing `&`, `#` and literal `+`,
  preserving configured categories/filters and special-episode separators.
- **Tanuki branding**: updated product name, supplied logo/icon assets,
  repository links, release metadata and English documentation.

See [Library tools](https://github.com/KvasExpert/Tanukarr/blob/v1.0.0/docs/library-tools.md), [Jellyfin refresh](https://github.com/KvasExpert/Tanukarr/blob/v1.0.0/docs/jellyfin.md),
[FORK.md](https://github.com/KvasExpert/Tanukarr/blob/v1.0.0/FORK.md) and the [documentation index](https://github.com/KvasExpert/Tanukarr/blob/v1.0.0/docs/README.md) for setup,
design and source attribution. The integrated upstream snapshot is Sonarr
`develop@57816c149`; this is not a promise to follow the latest upstream head.

The maintained [metadata provider guide](https://github.com/KvasExpert/Tanukarr/blob/main/docs/metadata-providers.md)
explains catalogue scope, per-title selection, implemented credentials and
provider identity. TheTVDB uses SkyHook without a personal API-key setting;
TMDB metadata uses a v3 API key, while public AniList/Jikan lookup and
authenticated AniList list import have distinct access requirements.

The current `main` source subsequently adds
[anime season and movie groups](https://github.com/KvasExpert/Tanukarr/blob/main/docs/anime-season-groups.md)
with official prequel/sequel discovery, manual overrides and grouped library
presentation. Generated paths can use configurable numbered season, story-arc
and movie leaves under one common anime or movie-saga folder. Existing paths,
catalogue identities and native episode numbering are
preserved. This post-release feature requires a build containing its source
commit and is not included in the immutable `v1.0.0` tag or its release images.

## Verification and limits

The [1.0.0 verification report](https://github.com/KvasExpert/Tanukarr/blob/main/docs/releases/1.0.0-verification.md) distinguishes the checks
executed for this release from earlier checkpoints. Historical Tanukarr
reports retain their tested versions, image identities and counts; current
product terminology is used in archive prose.
The AniList and Nyaa reports show earlier corrected builds; those results alone
do not verify the new branded release artifact. Current metadata audit also
identified ordering integration limits: non-TMDB owners ignore TMDB group
choices, and IMDb ordering/index options are not connected to a functional
production ordering path. Those limitations are documented in the
[maintained provider guide](https://github.com/KvasExpert/Tanukarr/blob/main/docs/metadata-providers.md)
without changing the immutable release artifacts or historical fixture results.

The native standard SQLite ZIP backup/restore worked again in disposable
populated fixtures on the corrected Tanukarr 1.0.0 image. **Standalone raw-XML restore remains an
unsafe inherited path**; use application ZIP backups and retain a separate
stopped-container configuration backup. PostgreSQL requires a separate database
backup/restore. Backups contain unencrypted settings/credentials and exclude
media. See [compatibility and backups](https://github.com/KvasExpert/Tanukarr/blob/v1.0.0/docs/compatibility-and-backups.md).

The corrected local image's offline Trivy scan still records 15 distinct CVE
IDs (three high, nine medium and three low), matching the earlier AniList
checkpoint's advisory set. Counting package/version/fix pairs gives 19 findings;
database updates were skipped. A passed build or functional suite is not a
zero-vulnerability certification. Refer to the exact release's SBOM, scan
findings and verification evidence. Public AniList lookup
and mocked authenticated GraphQL do not establish private-account OAuth sync;
Nyaa RSS search tests do not establish live download-client acquisition or
successful imports of the owner's media library. Generated-video Jellyfin
tests have the scope recorded in their own report.
