# Tanukarr 1.0.4

Tanukarr 1.0.4 adds optional Jellyfin watched-state synchronization, guarded
progress updates to supported originating list accounts, and correct task
timestamps after a successful manual backup. TV, anime and registered related
movie files use the same physical-file matching rules.

**Published and deployed on 2026-10-14:** exact amended source `fee14c10…`,
all three hosted workflows, nine downloaded release assets and thirteen runtime
reports (**231 checks**) were verified. Fresh hosted checks passed 7,811 backend,
115 frontend and 29 generated-media worker tests. The local native suite passed
7,855 distinct tests, including 206 focused regressions as a subset. The upgrade
preserved the existing library/list configuration and added only the approved
watched/progress schema. The published image retains 49 vulnerability occurrences,
including 21 High findings and zero detected image secrets.

On the exact published image, Backup and watched-counter browser checks each
passed four assertions through SignalR without reload. A fresh real disposable
Jellyfin run passed 23 checks and observed local watched counts **0 → 1 → 2**;
origin progression was tested only against an owned TLS AniList double.

## Changes since 1.0.3

- **Jellyfin watched state.** Opt in under Settings > Connect, choose one user
  and library, and poll at a configurable interval from 1 to 1,440 minutes
  (default 5). Registered file paths map played state to local episodes. Optional
  unmonitoring and guarded remonitoring are separate controls. An immediate
  **Sync Jellyfin Watched** task is available.
- **Source-list progress.** Enable writes both on the Jellyfin connection and
  each supported enabled import list (**Enable Automatic Add** on). AniList and official MyAnimeList advance an
  existing own-account episode counter; Trakt and SIMKL write explicit watched
  episode history with authenticated identity and native-numbering checks.
  Public/foreign lists and unsupported mappings remain read-only. The persistent
  queue retries eligible writes without losing local watched state and scopes
  pending progress to one verified Jellyfin watched source.
- **Backup task timing.** A successful manual backup now refreshes Last Execution,
  Last Duration and Next Execution under System > Tasks. It remains a manual ZIP
  and starts the next configured backup interval from the latest successful run.
  A failed backup retains its command error and the preceding successful timing.
- **Release gates.** Docker verification adds actual ZIP/timestamp/failure checks
  and a disposable local Jellyfin played-state check before image publication.
  All thirteen required hosted reports executed and passed on one verified image.
- **Current repository identity.** Maintained GitHub links use
  **KvasExpert/Tanukarr**. Historical image digests, source authors and release
  evidence keep their recorded identities.

Read the [Jellyfin watched guide](https://github.com/KvasExpert/Tanukarr/blob/main/docs/jellyfin-watched.md)
for setup, path translation, provider capabilities, continuous progress and
retry behavior. Existing library-refresh modes and the 1.0.3 hourly quality/codec
policy remain available.

## Installation and upgrade

Use the [Docker installation guide](https://github.com/KvasExpert/Tanukarr/blob/main/docs/docker-installation.md)
and the release's verified manifest/digest. The published image is
`ghcr.io/kvasexpert/tanukarr:1.0.4`; its Linux amd64 manifest is
`sha256:6b57ad2f00409f641bac5622437f46cd8b22e050d2e74b58dcf905c280301494`.
Preserve the existing configuration and media mounts, Compose project identity,
port and authentication. Take a consistent private backup before upgrading.

New watched synchronization, unmonitor/remonitor options and source-account
writes default to **off**. The database migrations add watched state and a
persistent progress queue. API v3/v5 and Sonarr's inherited assembly/database
compatibility names remain supported. Restore a backup into a separate
configuration when validating or rolling back migrations.

on GPT-6**. The supplied Tanuki artwork retains its recorded provenance.

A generated-video local Jellyfin check, provider fixtures and hosted runtime
checks establish their own scopes. No live external account write or playback
test against an owner's media is claimed. Owner follow-up checks were read-only.
Security findings and remaining dependency limitations belong to the publication
report.

At the original checkpoint, the local Jellyfin check observed native watched counts **0 → 1 → 2** and the
same progression in an owned TLS AniList API double, with idempotent repeated
polls. The separate browser displayed **2/3 → 1/3 → 2/3 watched** through live
SignalR without reloading. Native TV/anime/movie file rows were seeded in the
owned Tanukarr database and mapped to real generated media scanned by Jellyfin;
this does not establish a production download/import or a public AniList account
mutation. All owned fixtures were removed.
