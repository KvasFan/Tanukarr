Tanukarr 1.0.1 brings the grouping, list-import and browser reliability work
published after the first Tanukarr release into a new version for **TV series,
anime and related movies**. It retains per-title TheTVDB, TMDB, AniList and
MyAnimeList/Jikan metadata, original provider identities and Sonarr-derived
library, download and import workflows.

Source: [KvasExert/Tanukarr](https://github.com/KvasExert/Tanukarr).
Tag: `v1.0.1`. Docker image: `ghcr.io/kvasexert/tanukarr:1.0.1`.
The [release verification report](https://github.com/KvasExert/Tanukarr/blob/main/docs/releases/1.0.1-verification.md)
records executed checks, exact source/image identity and publication state.
Use the image after the publishing workflow has completed; these notes alone do
not establish that an image or release asset is available.

## Changes since 1.0.0

- **Adding titles:** Add New Series preserves the selected provider's recommended
  nonstandard series type when saved settings mount. TV/anime catalogue
  selection, credentials and ordering limitations are documented explicitly;
  sources are chosen per title, rather than automatically merged.
- **Grouping:** related series/anime entries and movies can appear under one
  title with configurable season, story-arc and movie folders. AniList/Jikan
  automatic discovery uses official supported prequel/sequel chains; manual
  grouping remains available for every catalogue owner. Native provider IDs,
  episode numbering and existing paths are preserved.
- **Safer grouped list additions:** group-slot collision recovery addresses the
  reported `UNIQUE constraint failed: Series.AnimeGroupId,
  Series.AnimeGroupMemberKind, Series.AnimeGroupSeasonNumber` import failure.
  Membership is rechecked immediately before persistence. If another addition
  occupies the same slot while metadata is loading, only the conflicting list
  candidate stays pending; valid additions are saved and counted accurately.
  Season and movie slots remain separate, and existing members are not moved or
  renumbered. Manual conflicts return a structured validation error. Unique
  database safeguards stay enabled; no schema migration or index removal is used.
- **Search:** native and grouped season panels offer **Search Season Packs**,
  using the member's actual series ID and native season. Complete-series searches
  include complete single-season packs and multi-season packs while automatic
  whole-series acquisition retains stricter coverage rules. Nyaa begins with at
  most three distinct title queries and requests supplemental packs only where
  coverage is missing. Cached-release acquisition rechecks the actual mapped
  native season coverage. Searches do not start downloads without an acquisition
  action.
- **AniList controls:** clearer grouped settings, **Load custom lists** name
  choices and manual custom-list names preserve OAuth and inclusion/exclusion
  precedence. Unknown membership and partial responses retain the previous
  successful list.
- **AniList reliability:** bounded public metadata/relation reuse, remaining-quota
  pacing and progress-preserving metadata additions reduce repeated work. After
  a witnessed complete list fetch, unchanged eligible settings allow pending
  additions to resume on the normal five-minute task without refetching private
  pages. The witness resets on restart and is invalidated by failures or settings
  changes. Provider rate limits still apply.
- **Library rendering:** the covered-library CommonJS component export correction
  resolves the reproduced React #130 failure in library views with cover images.
- **Expected cloud-policy messages:** intentionally blocked Sonarr cloud requests
  from system-time and scene-mapping checks use precise expected-block handling;
  other failures retain their normal warnings/errors. The banned upstream update,
  reporting and service endpoints remain disabled.
- **Tanuki branding:** GitHub's README displays the supplied Tanuki PNG directly;
  the original image is also provided for repository social-preview configuration.
  Application logos and original artwork provenance are preserved.

Selected-library Jellyfin refresh, Nyaa query encoding, guarded numbering,
multi-season packs, fake-release filtering and the other credited fork features
remain included. Feature behavior and configuration are described in the
[documentation index](https://github.com/KvasExert/Tanukarr/blob/v1.0.1/docs/README.md).

## Install or upgrade with Docker

Use the [installation guide](https://github.com/KvasExert/Tanukarr/blob/v1.0.1/docs/docker-installation.md)
for complete Compose YAML, storage permissions, authentication and offline image
loading. For a published image:

```sh
docker pull ghcr.io/kvasexert/tanukarr:1.0.1
```

Take a consistent `/config` backup first. Change the existing Compose image to
`ghcr.io/kvasexert/tanukarr:1.0.1`, preserving its configuration volume or bind
mount, media mounts, Compose project identity, ports and authentication. Then
run:

```sh
docker compose pull
docker compose up -d
docker compose ps
```

Recreating the container applies the new image; restarting the old container
does not. Do not replace an existing config volume with a new empty volume or
share a live `/config` with another Sonarr instance. Check each release's
published architecture and digest. The release workflow targets **Linux amd64**;
no untested platform support is implied.

**1.0.1 is the product version.** The inherited Sonarr core remains `10.0.0.*`.
The `Sonarr` executable, `config.xml`, `sonarr.db`, database history and container
port 8989 retain their compatibility names. API v3 and v5 are supported; v4 is not
implemented. See [compatibility and backups](https://github.com/KvasExert/Tanukarr/blob/v1.0.1/docs/compatibility-and-backups.md).

## Verification and limits

The [1.0.1 verification report](https://github.com/KvasExert/Tanukarr/blob/main/docs/releases/1.0.1-verification.md)
separates this release's executed checks from earlier feature checkpoints. It
also records remaining security findings and skipped or unavailable checks.
The local release candidate passed the solution build, **7,184 Windows backend
tests** (19 ignored), **7,180 Linux backend tests** (27 ignored), **75 frontend
tests**, **29 worker tests**, **104 runtime fixture checks** and Chrome checks
on all three covered-library views. Focused regressions are subsets of the broad
backend totals. Docker fixture checks include the reproduced group-slot race;
the nine Jellyfin checks use a real disposable server with generated media.
Deployment preserved the then-current 100-series library, one list and 99 cached
items. These are local checked-image results; exact hosted release identity and
publication are supplied by the release artifacts and workflow receipts.
The earlier [grouping](https://github.com/KvasExert/Tanukarr/blob/main/docs/anime-season-groups-verification-2026-10-13.md)
and [AniList/browser reliability](https://github.com/KvasExert/Tanukarr/blob/main/docs/anilist-react-reliability-2026-10-13.md)
reports retain their original tested source and image identities; their counts
are not presented as new 1.0.1 results.

The exact local image's cached-database Trivy High/Critical scan reported zero
Critical findings, three High ImageSharp advisories and zero detected secrets.
This release does not claim an ImageSharp upgrade or zero vulnerabilities. Use
the verification report and release SBOM for actual image findings.
The PostgreSQL group-constraint recovery path is reviewed in source;
no PostgreSQL runtime verification is claimed.
AniList's server allowance can still be exhausted by other applications sharing
a public IP. Mocked OAuth GraphQL, searches and generated-video tests do not
establish downloads or imports of the owner's real media.

Use standard application ZIP backups and keep a separate stopped-container
configuration backup. The inherited standalone raw-XML restore limitation
remains; PostgreSQL requires a separate database backup. Backup archives can
contain unencrypted credentials and do not contain media.
