# Tanukarr 0.1.0 publication

This page records source-qualified verification for native film support,
mixed collections, library import and dependency/container hardening. Public
distribution verification is pending at this preparation checkpoint. No new
image digest or asset checksum is claimed before it is checked.

The [maintenance ledger](0.1.0-maintenance-verification.md) retains intermediate
failures and their fixes. The [initial publication checkpoint](0.1.0-publication-initial.md)
preserves the earlier source `90d18969`, image, assets and executed tests.

## Preparation evidence

- A complete local backup was verified before implementation: nine GitHub asset
  digests, a full Git bundle and consistent snapshots of two local configurations.
  Restored SQLite copies returned `ok` from the integrity check.
- Windows solution builds passed with zero warnings/errors. Native test results
  are recorded by checkpoint in the maintenance ledger; focused runs are not
  added to full-suite totals.
- Frontend passed 211 tests, ESLint, Stylelint, TypeScript and the Vite build.
  The production bundle has no large-chunk/font warning. Route splitting retains
  the complete historical timezone database as a separately served asset.
- Genuine PostgreSQL 17 passed 28 collection migration/range/concurrency cases.
  The disposable server was removed afterward. Hosted CI repeats these tests
  through the checked-in PostgreSQL fixture.
- Candidate 1 upgraded a populated schema252 library to schema253. Existing
  provider/episode/file identities, monitoring, paths and bytes survived migration,
  rescan, owning-provider refresh and restart. This is a generated library,
  not the owner's library.
- Candidate 2 passed actual Jellyfin watched-state and selected-library refresh
  checks, including generated imports, real scheduler ticks, restart persistence,
  user isolation and recovery from an unavailable server.
- Actual movie downloads exposed an API grab guard that accepted only TV season
  coverage. Both API versions now have separate strictly validated movie contexts;
  final container download verification remains required for this fix.
- Candidate 3c passed 38 packaged GUI checks, including native movie Library
  Import with unchanged generated bytes, movie search, separate movie/TV indexer
  categories and desktop/touch Settings routes. The inner browser recorded 31
  checks, zero JavaScript errors/warnings and zero external requests. Its 168
  PNGs are retained; visual reviews are recorded separately by checkpoint.
  Candidate 3c
  also passed 11 backup/task/archive/scheduler/recovery checks, including the
  actual Backup button updating task timing through SignalR without a reload.
- First-run desktop/mobile Chromium and genuine UID/GID1001 functional checks
  passed on candidate 2. Both account-creation PNGs were individually inspected.
  Independent nested-base login/navigation passed without missing assets or
  JavaScript errors. These results do not substitute for the final image rerun.

## Security inventory and limits

Candidate 2 was scanned with verified Trivy 0.76.0 and the current database:
19 runtime OS vulnerability occurrences, representing 15 CVEs, with zero Critical,
zero High, 14 Medium, five Low and zero detected image-layer secrets. RootFS and
image identities were checked. ImageSharp was removed from production dependencies;
these are candidate results, not yet a scan of the public release image.

One high-severity `braces` advisory remains in build-only dependencies with no
published patched version. The Docker configuration scan retains DS0002 because
startup prepares the configured user/configuration ownership before dropping
privileges. Runtime tests verify the unprivileged process, no capabilities,
no-new-privileges and removal of unused setuid/setgid mode bits. These distinct
findings are not suppressed or combined into a misleading clean-scan claim.

An inherited ConfigService Trace message exported raw setting values, including
API keys and generated salts. The message now retains setting names and actions
without values. Actual NLog memory-target tests passed; the final movie fixture
also checks raw Trace logs before report redaction.

The [initial image inventory](0.1.0-image-security-initial.json) retains its own
source-qualified scan. The current public-image inventory will be updated only
after the delivered immutable image is checked.

## Verification scope

Checks use owned disposable configurations, generated media, local HTTPS
catalogue fixtures and actual local qBittorrent/Jellyfin servers. No live TMDB
or OMDb key was supplied, so provider tests establish HTTP/JSON contracts and
native identity behavior rather than live account/catalogue accuracy. Downloads
use only owned local torrent/web-seed payloads. No owner library was downloaded
into, renamed, moved, rescanned or upgraded by these tests. GPU encoding, ARM
runtime images and arbitrary private indexer/provider accounts are not covered.
