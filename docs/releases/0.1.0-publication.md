manifest/config bytes were hashed independently; source/version labels and all
eight filesystem layer identities agree with the hosted image and pulled image.
`0.1.0` and `latest` resolve to the same manifest. Trivy 0.75.0 scanned that

The 54 vulnerability occurrences represent 20 distinct CVEs and 24 package/CVE
pairs. All High findings concern ImageSharp 3.1.12. Repeated dependency manifests
contribute repeated occurrences. OS findings have no fixed package version
advertised by the selected scanner feed. The
[sanitized inventory](0.1.0-image-security.json) preserves exact installed/fixed
versions, scanner metadata and separately checked vendor remedies.

The registry config digest is independently verified. Trivy `ArtifactID` is a
scanner analysis/cache identity, recorded separately as `scannerArtifactId`;
it must not be used as a registry config digest. Earlier local inventory labels
were corrected in a separate retained follow-up without altering raw reports.

The vendor's updated [ImageSharp advisories](https://github.com/SixLabors/ImageSharp/security/advisories)
list fixes for the five scanned ImageSharp CVEs in **3.2.0 and 4.1.2**. The
[3.2.0 release](https://github.com/SixLabors/ImageSharp/releases/tag/v3.2.0)
backports security fixes and introduces direct-reference license enforcement.
Inspection of its actual NuGet build targets confirms Release key validation;
no upgrade build or compatibility test was performed. The
[vendor documentation](https://docs.sixlabors.com/articles/imagesharp/)
describes free assembly-scoped community keys for eligible open-source projects,
including contributor builds. No project key was supplied for this release and
no license application was submitted. This adds the licensed v3 backport remedy
to the preparation notes' discussion of the fixed major version.

The build-only braces advisory remains unpatched at the primary-source recheck;
Node/Yarn are absent from the application runtime image. This is not a claim
that the release is free of known vulnerabilities.

owner's library. No owner deployment or private-provider account write was
tested. Public catalogue checks are read-only and separately identified.
GPU encoders and ARM images are not validated by these checks.
