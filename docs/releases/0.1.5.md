# Tanukarr 0.1.5

Tanukarr **0.1.5** identifies series by their database ID in page addresses and
allows two series to share a title slug. It is adapted from upstream Sonarr. All
0.1.4 features, the v3/v5 APIs and the provider identities are kept.

The database schema moves from 253 to **254**. Back up the configuration before
upgrading. An older image cannot open a schema-254 database, so a rollback needs
the backup taken before the upgrade.

## Changes

### Series addresses

- **Series pages use the series ID.** Series pages are now at
  `/series/<title-slug>/<id>`. All links to a series page use this form,
  including the links from:
  - the library and its collection, season and member covers;
  - the header search;
  - Add New Series results for series already in the library;
  - the queue, history, blocklist, Wanted and parse screens.
- **Old addresses keep working.** Bookmarks and links of the form
  `/series/<title-slug>` redirect to the ID address and keep a requested
  collection season (`?season=N` and `#season-N`). If a series is renamed and
  its slug changes, the ID address follows the new slug.

### Library

- **Duplicate title slugs are allowed.** Migration 254 replaces the unique index
  on `Series.TitleSlug` with a non-unique one. Two series whose titles produce
  the same slug can now both be added; adding the second one no longer fails
  with "Title slug is in use". This affects, for example:
  - anime collection members with the same title from different catalogues;
  - remakes with the same name.

  Series remain unique by catalogue ID and path.

## Reviewed and not imported

Upstream's *path updated after a move* and *TMDb Import Lists* features were
reviewed. Tanukarr already carries KakarottoCake's implementations of both, so
neither was imported. Tanukarr's TMDb lists use the user's own TMDB read-access
token. Upstream instead exchanges tokens through `services.sonarr.tv`, which
Tanukarr does not contact.

## Upgrade

Pull `ghcr.io/kvasfan/tanukarr:0.1.5` and recreate the container. Migration 254
runs once at startup, and 0.1.0 to 0.1.4 configurations upgrade directly. No API
fields changed. API callers that relied on title slugs being unique should look
series up by `id` instead.

## Installation and verification

Use the [Docker installation guide](../docker-installation.md). The published
image is `ghcr.io/kvasfan/tanukarr:0.1.5`; `latest` selects the tested release.

The release follows the 0.1.4 procedure. The application code passed the full
gate profile on `main`, and the release tag runs the light profile. The
[verification ledger](0.1.5-verification.md) records the local and hosted checks
that were run. Do not describe this release as vulnerability-free: the 0.1.0
security inventory is still the latest recorded scan of the public image.
