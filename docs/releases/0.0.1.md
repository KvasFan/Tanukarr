# SonarrWeeb 0.0.1

> Historical checkpoint: this project is now **Tanukarr**. See the [current documentation](../README.md) and [Tanukarr 1.0.0 verification](../releases/1.0.0-verification.md). Original SonarrWeeb names, versions, image references and test results below describe the recorded build and remain unchanged.

SonarrWeeb 0.0.1 packages the integrated Sonarr fork under its own project name
and release version. The source combines upstream Sonarr `develop` through
`57816c149`, KakarottoCake's Sonarr Pro, compatible gaboy498-byte and ikatun
features, and local provider, numbering, functional and security fixes.

Source: [KvasExert/SonarrWeeb](https://github.com/KvasExert/Tanukarr).
Git tag: `v0.0.1`. Container: `ghcr.io/kvasexert/sonarrweeb:0.0.1`.
The initial release supports **Linux amd64**. An arm64 image is not included.

## Installation

Use the [Docker installation guide](https://github.com/KvasExert/Tanukarr/blob/v0.0.1/docs/docker-installation.md) for complete
Compose YAML, configuration volumes, filesystem permissions, authentication,
download paths, updates and offline image loading. Download `compose.yaml` from
the release into a separate installation directory, create writable `config`
and `media` directories, then run:

```sh
docker compose config
docker compose pull
docker compose up -d
```

Open **http://localhost:6970** and configure authentication, root folders,
indexers and download clients. The example binds to loopback and maps host port
6970 to container port 8989. PUID/PGID default to 1000, TZ to `Etc/UTC`, and UMASK
to `002`. The release YAML uses `SONARRWEEB_*` overrides and retains configuration
under `/config`.

The GHCR package must be published and public for anonymous pulls. A public
repository alone does not establish package visibility. The release manifest
and [release verification](https://github.com/KvasExert/Tanukarr/blob/v0.0.1/docs/releases/0.0.1-verification.md) identify the actual published
image, artifact checksums and executed checks.

## Included features

- Per-series TheTVDB, TMDB, AniList and MyAnimeList/Jikan metadata ownership,
  with native provider identities preserved throughout lookup and library use.
- TMDB episode-group and IMDb ordering options, absolute-number matching,
  multi-season packs and scene/library numbering safeguards.
- Complete-series interactive search and dry run, pack-first automatic search,
  monitored-season rules, queue coverage and requested-season handling.
- Torrent fake-release filtering, season-pack trimming, retained-version
  controls and optional host-side compression.
- Import-list preview, synchronization, exclusions and cleanup using native
  metadata-source/foreign-ID ownership. AniList account-list statuses, anime
  release statuses and custom-list membership remain separate, combined filters.
- Library/path filters, pause controls, search diagnostics, guarded restore
  and restricted companion keys.
- Corrections for TMDB key exposure in logs, optional-worker network access
  through disguised playlists, companion add-payload restrictions, filesystem
  path guarding, AniList UI attribution and container file permissions.

See [README.md](https://github.com/KvasExert/Tanukarr/blob/v0.0.1/README.md), [FORK.md](https://github.com/KvasExert/Tanukarr/blob/v0.0.1/FORK.md) and
[Library tools](https://github.com/KvasExert/Tanukarr/blob/v0.0.1/docs/library-tools.md) for feature behavior and configuration.
The optional compression worker runs separately on the host and is not included
as a running service in the main image.

## Version and migration compatibility

**0.0.1 is the SonarrWeeb product release version.** The inherited internal
assembly/core version remains `10.0.0.*` for Sonarr runtime and upgrade
compatibility; it is not an additional SonarrWeeb release number. The V5 API and
supported legacy V3 routes retain their existing contracts. Check the release
manifest for the precise internal runtime version of the packaged build.

Database migrations include the integrated fork history through migration 242.
Copy an existing upstream configuration into a separate SonarrWeeb configuration
location after taking a consistent backup. Never share a live `/config` between
instances. Migrations can prevent upstream Sonarr or an older build from opening
the copy; retain the original backup and use separate download categories.

Updates are delivered as containers. Shared upstream update, crash-report and
announcement services remain disabled. No in-app updater should replace this
fork with upstream Sonarr.

## Verification and known limits

The [October 12 security and functional audit](https://github.com/KvasExert/Tanukarr/blob/v0.0.1/docs/security-functional-validation-2026-10-12.md)
records 7,239 Windows and 7,075 Linux test passes, 16 frontend tests, 29 worker
tests, 19 runtime checks and five Chromium scenarios, with recorded skips and
platform restrictions. Those results apply to the source and image hashes in
that report. They are historical evidence for the integration, rather than a
claim that release packaging repeated every suite. Release-specific checks and
publication evidence are recorded in [0.0.1 verification](https://github.com/KvasExert/Tanukarr/blob/v0.0.1/docs/releases/0.0.1-verification.md)
and the attached reports.

Residual findings from that audit remain relevant:

- ImageSharp 3.1.12 has five recorded CVEs: three high and two medium. The known
  TIFF/ICC paths are excluded by the current JPEG/PNG/WebP resizer configuration
  and were tested, but the library has not been patched. Upgrading to the fixed
  4.x package requires resolving its Release-build license-key requirement.
- Ten Ubuntu CVEs were reported at the earlier scan checkpoint, with no fixed
  distribution package then available. The release SBOM identifies the actual
  component versions; a component inventory alone is not a new vulnerability scan.
- The build-only `braces` advisory has no fixed version in the recorded audit.
  Node and its frontend build dependencies are absent from the runtime image.
- Three legacy upstream migrations, 029/030/033, interpolate text already stored
  in very old databases. No current API exploit was demonstrated; this remains
  a migration hardening concern.

No authorized real-library download/import, private AniList/OAuth account-list
synchronization or VAAPI hardware encode was observed. Public AniList requests
and disposable fixtures exercise native identities and list-filter distinctions.
Torrent filtering remains heuristic, and native media parsers were not
comprehensively fuzzed. The audit is not a security certification.
