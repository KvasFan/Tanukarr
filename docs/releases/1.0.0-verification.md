## Findings corrected during verification

The first native image-resizing run failed an inherited 30,000-byte output cap
tied to the old logo. The supplied artwork produced a valid 170×170 PNG larger
than that cap but substantially smaller than its source. The test now checks
nonempty output smaller than the source and still checks decoded dimensions;
production resizing code was unchanged. The focused image cases and subsequent
full Core runs pass.

An intermediate image built and passed backend suites but failed functional
setup because General settings still required a Sonarr-only instance name,
rejecting the new `Tanukarr` default. The shared validation now accepts an
anchored `Tanukarr` or legacy `Sonarr` prefix/suffix, preserving the prior policy.
Twenty-six new real PUT-validation cases and the full API suite pass. The
intermediate `7c995755…` image and its successful isolated calendar checks are
retained as diagnostic evidence, not certified as the final release image.

The macOS ICNS writer initially used PNG frames for small icons. Format review
led to `ic04`/`ic05` straight-ARGB frames with PackBits channel encoding and
larger/Retina PNG frames. Decoded channels match source artwork bytes. This is
binary-format verification, not an executed macOS Finder/AppKit test; the
research contributor is credited in [CONTRIBUTORS.md](../../CONTRIBUTORS.md).

above; repeated dependency manifests must not be presented as newly introduced

`deployment.json` records the local replacement and preservation checks; its
private configuration backup remains outside the source tree and release assets.

`legacy/sonarr-pro/v1.0.0`, retaining its original tag object and annotation.
The new Tanukarr `v1.0.0` refers to the tested, independently packaged release.

## Known limitations

The raw-XML restore path remains unsafe and is not certified by successful ZIP
restore tests. Use standard application ZIP backups; PostgreSQL needs a separate
database backup/restore. Backups contain unencrypted credentials and omit media.
Earlier scans recorded remaining dependency/OS advisories; no zero-vulnerability
claim is made. Private AniList OAuth synchronization, live download-client
acquisition, the owner's real media library, arbitrary decoder fuzzing and
unexecuted architecture/platform combinations remain outside the recorded
historical fixture tests unless specifically verified above.

The supplied Tanuki artwork is attributed to the project owner's
`Tanuki_Logo.zip` archive; no original artist identity or license was established
in this session. Source authors and original license/copyright notices remain
credited and unchanged. Local adaptation uses **OpenAI Codex based on GPT-6**.
