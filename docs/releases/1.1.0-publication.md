## Functional scope

**Collections:** Forms-authenticated Chromium exercised generated anime chains, mixed TV/movie groups, movie sagas, native multi-season TV and Specials. It verified native season navigation, real refresh commands, all-member interactive searches, pack/episode filters, settings persistence and unchanged native identities/paths. Covers decoded at display densities 1/2/3, a controlled missing thumbnail retried the original, and desktop/mobile scrolling worked. Four screenshots carry hashes, byte lengths and dimensions. There were no JavaScript errors or external requests; only expected controlled-404 console messages occurred.

**Custom qualities:** v3/v5 exercised creation, copy, rename, edit, retirement/restoration and profile factors. Actual release decisions and import previews agreed for a generated 4K HEVC file; normal import preserved its bytes and native season folder. Rescan/restart retained identity and settings, and six concurrent enable/delete attempts retained safe states. RSS responses were local fixtures; no public acquisition was attempted.

**Artwork:** trusted, isolated catalogue/CDN fixtures verified AniList/MAL and TVDB/TMDB fallback through exact existing IDs, preservation of owner presentation and native episodes, canonical root artwork when that root was absent from the saved library, mismatched-ID rejection and shared 429 cooldown. These checks did not contact live alternative catalogues or private accounts.

**Jellyfin Connect:** a real disposable pinned Jellyfin server exercised selected-library immediate, interval and combined refresh, real one-minute scheduling, burst batching, restart persistence, outage recovery and stale/uninitialized-library rejection. Five generated files used normal Tanukarr import APIs; identity/episode rows were seeded directly. Other libraries remained unchanged after the initial bootstrap scan. Separate watched tests incremented actual Jellyfin play counters and Tanukarr progress, tested selected-user isolation, monitoring ownership, restart/outage recovery and native TV/anime/movie matching. Originating-account writes used an owned TLS AniList double, not a public account; watched-test Tanukarr file rows were seeded directly.

**Download client and folders:** genuine qBittorrent **5.2.4 / API 2.15.1**, generated credentials and isolated storage exercised v3/v5 Add, Edit, Test, masked Get and Delete. Five generated videos were manually imported/rescanned into logical anime seasons, standard TV seasons, mixed movie-title folders and saga `Film 01/02` folders, preserving bytes and native identities. Both queues stayed empty. Completed-torrent automatic import and public downloads were not tested.

These fixtures did not access owner configuration or the owner's real library. The release manifest's conservative legacy `browserUITested`, `realLibraryTested` and `downloadsTested` flags remain false; detailed collection-browser evidence establishes the generated/disposable UI scope above, without extending it to private libraries or public acquisition.

## Security findings and limits

Fresh Trivy **0.75.0** scanned the actual pulled public manifest above with all severities and vulnerability/secret scanners. Its vulnerability database was updated **2026-10-13 at 19:11 UTC**. The inventory reports **49 occurrences, 15 distinct CVEs and 19 package/CVE pairs**: zero Critical, **21 High**, 23 Medium and five Low, with **zero detected image secret matches**. Every package/version/CVE/severity/fixed-version/occurrence tuple matches the earlier local-image checkpoint; the public scan was executed separately, not inferred from that checkpoint.

Actual shipped dependency/runtime documents confirm .NET and ASP.NET **10.0.13**, four SignalR assembly witnesses and two Pkcs witnesses at that patch. The SDK is **10.0.402**. The direct Pkcs reference overrides the older transitive minimum; audit checks remain enabled.

ImageSharp remains **3.1.12**, with 35 repeated occurrences of five CVEs; the scanner advertises **4.1.2** as fixed. The previously verified 4.1.3 Release upgrade requires a valid Six Labors key. Bounded decoder safeguards do not establish that those CVEs are patched. The other 14 occurrences concern Ubuntu glibc, ICU, PCRE2, systemd/udev, shadow login/passwd, tar and zlib packages, with no fixed version advertised by this inventory. The [public image-security inventory](1.1.0-image-security.json) records the exact identifiers, installed versions, severities and repeated occurrences. It is a retained summary of this scan, not a continuously updated advisory feed.

The frontend audit retains three High `braces` build-tooling occurrences; Node/Yarn are absent from the runtime image. The preserved source scan covers 98 explicit production C# files with 27 rules and eight INFO authorization reviews, zero parse errors. Neither scan establishes exploitability or a whole-repository security guarantee. Runtime owner volumes were not scanned, and no clean-dependency claim is made.

## Protected deployment

The owner instance was upgraded from **1.0.5 / schema 250** to the immutable public **1.1.0 / schema 252** image. A stopped-container copy of the configuration was saved under the local tool directory's private backup area, with inherited access disabled and access limited to the owner, SYSTEM and Administrators. The backup and stopped original passed SQLite integrity and preservation comparisons before recreation. Existing configuration/media mounts, published ports and Compose service identity were retained.

The migration comparison at **11:09 UTC** passed for all **37 prior protected tables**, preserving their old columns and rows. Only migrations **251/252** and the seven approved additive columns were accepted: five quality-definition criteria/retirement columns, profile `CodecMultipliers` and series `CollectionTitle`, with approved defaults. No new table was added. Raw before/after hashes remain in the private checkpoint. Volatile task/status tables and the documented search-history fields were excluded; this is not a byte-identical database or all-field preservation claim. No configuration restore or media movement was performed.

Read-only v3/v5 status checks at **11:11 UTC** reported Tanukarr **1.1.0**, core **10.0.0.18155**, .NET **10.0.13** and schema **252**. The instance retained **292 series, one enabled import list and 292 saved list items**; it had zero registered episode files, download clients or notifications. The API checks did not run provider Tests, add clients, change settings or initiate downloads. Unauthenticated `/series` served the configured Forms login with HTTP 200. A separate bounded browser check with the API key restricted to the same origin also reached the existing Forms login boundary; no login was submitted and no API mutation or outside request was allowed. Its zero JavaScript errors establish the login boundary, not owner-library React rendering. The authenticated packaged fixture browser establishes the full UI scope separately.

The bounded startup-log inspection found **zero Error/Fatal entries** and two warnings: ASP.NET's expected HTTP port override and an empty series root. The saved import root is still **`/tmp`**, which belongs to the container's writable layer. Before recreation it contained zero regular files, and the mounted media folder was empty. Existing paths/list settings were preserved. Configure a persistent root such as **`/media` before importing real media**; container recreation does not preserve `/tmp`. The [Docker installation guide](../docker-installation.md) explains persistent mounts and path updates.

The upgraded local instance is available at **http://localhost:6970/** using its existing authentication. Genuine qBittorrent and Jellyfin verification used the isolated generated fixtures above; the owner currently has neither integration configured.
