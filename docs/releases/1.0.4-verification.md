## Late authorization review and publication cancellation

After the original source was pushed, review confirmed that disabling global
Jellyfin list-progress writes or a per-list opt-in during the first provider
write did not reliably block the next target. The service was using settings
captured before the first dispatch. This was a **production contract gap** in
`0226d76b11a5dca854aaa81f6d8a722056c9daf1`, separate from the earlier optional
browser-helper failures described below.

The correction requires fresh authorization immediately before every writer
advance, including a current Jellyfin authorization callback, a fresh list
definition and matching native/target identity. New regressions replace the
repository-returned definitions during the first write rather than merely
mutating an aliased settings object. These checks must establish that a second
dispatch is blocked after revocation. An already in-flight writer advance may
contain several HTTP requests and remains outside the opt-out guarantee;
provider preflight/mutation also remains non-atomic.

A subsequent source review also confirmed that the original provider-only queue
fingerprint could retain user A's pending prefix 2 after selecting Jellyfin user
B with a current prefix 1. Reusing that pending value would write progress not
established by B's current watched source. The correction combines one exact
nonempty source fingerprint from the matched watched episode IDs with the
provider target identity. Missing/mixed sources are blocked, and a changed
source resets previous pending/acknowledged context before fresh remote
advance-only preflight. No migration or public episode DTO change is required.
The final amended native tests below include this source-isolation correction.

The first authorization-only amendment compiled with zero warnings/errors and
passed **201 focused regressions**: the preceding 177 plus 24 new guards.
That intermediate run does not verify the subsequent queue-source correction.
That intermediate checkpoint remains separate from the final amended native,
frozen-scan and thirteen new-image reports below; the original 231 image checks
remain historical.

## Watched-state scope and safety

The design reads one selected Jellyfin user/library, validates complete pages,
and matches registered physical file paths. Missing/unmatched items do not erase
local watched history. Monitoring changes and list writes are separate opt-ins.
Migrations 248/249 persist local state and queued progress. The private source
authority is omitted from public episode resources.

AniList/MAL scalar progress uses a watched continuous native episode prefix and
verified own-account existing entries. Trakt/SIMKL use explicit episode history
with compatible native identities. Provider fixtures and actual local Jellyfin
playback-state changes establish different scopes; neither proves a live private
external account accepted a write. See [Jellyfin watched status](../jellyfin-watched.md).
