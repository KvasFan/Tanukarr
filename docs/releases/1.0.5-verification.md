# Tanukarr 1.0.5 preparation and verification

This report records new evidence for the requested list-snapshot and native
provider preference changes. The
[1.0.4 publication](1.0.4-publication.md) retains its own source, image and test
checkpoint and does not establish results for 1.0.5.

## Initial investigation, 2026-10-14

- The pasted October 13 log's HTTP 429 occurred in AniList relation/grouping
  lookup after list processing. A complete list read alone cannot remove every
  grouping/metadata request.
- The log's relative `/api/v5/...` GET paths are incoming local API requests.
  The current repository blocks two shared Sonarr cloud endpoints through its
  existing request policy; no change to that policy is authorized by this release.
- Negative TVDB IDs are internal compatibility slots. Native catalogue IDs are
  retained separately. The older `[0]` addition log prints the incoming
  `TvdbId = 0` before metadata preparation, rather than the database series ID.
- A read-only check of the deployed 1.0.4 configuration found 292 series, one
  enabled list and a `/tmp` root, with zero registered episode files and zero
  reported media bytes. A persistent-root preference was requested separately;
  that question does not authorize moving saved paths without a response.
- Relevant import/provider paths differ from the pinned upstream base
  `57816c149d02f95543973fefb4780c4495f8121c`. Changes are scoped to the existing
  fork additions and the shared import lifecycle; this is not an attribution of
  a new upstream regression.

remain pending. The local native, frontend, worker, fourteen runtime reports and
preference browser checks above have executed successfully. Record new hosted
and publication results against their actual source and image rather than

from a later fresh synchronization, preserve independent inclusion/exclusion
