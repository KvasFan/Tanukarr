## Reported failure

The supplied 2026-10-13 log reports an `ImportListSync` insert failing with
`UNIQUE constraint failed: Series.AnimeGroupId, Series.AnimeGroupMemberKind,
Series.AnimeGroupSeasonNumber` on internal core version `10.0.0.24290`.
The previous locally tested image reproduces the exact exception in an owned
SQLite fixture: `tanukarr:anilist-react-fix`, image ID
`sha256:5ed5aeaf68233a7bc77886e712e69c162f3e0823a81f0bf812dcdaf8f5410997`,
revision label `anilist-react-reliability-2026-10-13`, product version 1.0.0,
internal core `10.0.0.24270`, .NET 10.0.12 and schema 247. These are the fixture's
observed identities, rather than an assertion that it is the owner's exact
`10.0.0.24290` runtime.

The deterministic scenario holds one metadata response after preparing a
season/movie batch, then adds a manual Season 1 occupant through the real API.
On that old image, `ImportListSync` fails with the same SQLite season-slot UNIQUE
error and all four prepared additions roll back. The manual occupant and the
four-entry successful list snapshot remain stored. The old-image invocation
passed seven checks with `--expect-old-failure`; this establishes the reported
failure and is not a pass of the repaired behavior.

The new `SeriesService` persistence boundary revalidates all prepared memberships
against current stored rows and earlier candidates inside a short, local
addition lock. Automatic list batches defer only a conflicting candidate and
publish/count rows that actually persisted. If an exact group-slot UNIQUE
violation still occurs after validation, the rolled-back object IDs are reset
before controlled per-candidate persistence; unrelated database exceptions are
not converted to success. Committed IDs still emit the import event if a later
unrelated database error propagates, so already saved members receive their
normal follow-up initialization. A real-SQLite regression covers that case.
Manual group-slot conflicts return a structured
validation error, represented as HTTP 400 at the API boundary. Season/movie
ordinal namespaces remain distinct, and existing stored assignments and paths
are preserved. No index is dropped, no schema migration is added and no member
is silently renumbered.

The SQLite classifier recognizes only the exact season/movie UNIQUE failure;
the PostgreSQL classifier recognizes only `23505` for the two named group-slot
indexes. PostgreSQL runtime verification has not been performed. The final
fixed-image regression passed **12 checks** on the immutable local image
identified above, including an actual host UID/GID 1001 invocation and successful
owned-resource cleanup. The command completed after the race and saved Season 2,
Movie 1 and the unrelated entry, reporting three actual additions. The existing
manual Season 1 occupant and complete four-entry list snapshot stayed unchanged.
An unchanged retry completed with zero additions and no new membership fetch;
manual duplicate season/movie additions returned HTTP 400. Native S01 episode
identities remained separate from group ordinals, both unique indexes remained
present and the owned SQLite database passed `integrity_check`.

Two earlier positive-image harness attempts failed despite the expected product
persistence behavior: the first log assertion did not accept trailing horizontal
whitespace; the second indexed an optional null JSON property that the API
legitimately omits. The helper assertions were corrected without weakening the
database, native-identity or count requirements. Both failed receipts are kept as
`group-import-collisions-log-parser-first-attempt.json` and
`group-import-collisions-nullable-json-first-attempt.json`. The final
`group-import-collisions-report.json` passed all 12 checks with cleanup complete.
Native SQLite fixture results are included in the focused backend run above.

Reproduction receipts are ignored local files under
`_artifacts/release-1.0.1-2026-10-13/group-import-collisions-before.json` and its
sanitized `.log`. The reusable
[fixture](../../docker/tests/group-import-collisions.py) and
[instructions](../../docker/tests/README.md#concurrent-grouped-list-additions)
allow a separate invocation against another image without accessing the main
configuration, public AniList, account credentials or download clients.

## Publication boundary

The local image's descriptive revision label is separate from a Git commit and
a registry manifest digest. At this checkpoint, the release commit/tag and
hosted image publication were still pending. The
[CI workflow](../../.github/workflows/ci.yml),
[Docker workflow](../../.github/workflows/docker.yml) and
[release workflow](../../.github/workflows/release.yml) encode the hosted gates;
their configuration alone is not an observed pass.

After publication, use the actual
[v1.0.1 release](https://github.com/KvasExert/Tanukarr/releases/tag/v1.0.1), its
`release-manifest.json`, `SHA256SUMS`, source archive and verification receipts,
plus the [published GHCR package](https://github.com/users/KvasExert/packages/container/package/tanukarr)
for the released source commit, image digest, architecture and artifact identity.
A later hosted image must identify that exact committed source and pass its own
checks; the local image ID above is not presented as its future registry digest.
The immutable earlier 1.0.0 tag/assets are not replaced by this release.
