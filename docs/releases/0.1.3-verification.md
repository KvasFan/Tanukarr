## Release preparation

The release commit sets `VERSION` and the Dockerfile default to 0.1.3, adds
the release notes, and introduces the workflow's gate profiles: tags run the
light profile, every other event the full one. Checks executed for that change:

- The workflow parses (js-yaml); the step list shows that a tag runs the build,
  smoke, functional/security, fixture preparation (Python mock image and the
  earlier release image only), the earlier-image requirement, quality/codec,
  custom qualities, first run, library upgrade, report upload, registry push,
  SBOM, packaging and the release job, and skips the other nineteen steps.
- All 29 `run` blocks pass `bash -n`.
- Simulated with the workflow's own scripts: the light profile passes exactly
  four additional reports (quality-codecs, custom-qualities, first-run,
  library-upgrade) and `--gate-profile light` to the packager; the full profile
  passes the original 22 reports in their original order; first run receives
  the browser arguments only in the full profile.
- `docker/release/package.py` compiles and accepts `--gate-profile`
  (`full`/`light`, default `full`), which it records as `gateProfile` in
  `release-manifest.json`.
