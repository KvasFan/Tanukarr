Tanukarr 1.0.2 improves import-list selection and preserves the shared **TV,
anime and related-movie** library workflows. Metadata ownership, group folders,
complete-series/season-pack searches, Nyaa query handling, Jellyfin refresh and
the existing Sonarr-derived import/download tools remain available.

Source: [KvasExpert/Tanukarr](https://github.com/KvasExpert/Tanukarr).
Tag: `v1.0.2`. Image: `ghcr.io/kvasexert/tanukarr:1.0.2`.
Use the tag after the verified publishing workflow finishes. The
[1.0.2 verification report](https://github.com/KvasExpert/Tanukarr/blob/main/docs/releases/1.0.2-verification.md)
records actual execution, image identity, remaining findings and publication
state. Writing release notes does not establish that an image is published.

## Changes since 1.0.1

- **Predictable list selection:** select eligible entries from any configured
  included custom lists, or all eligible entries when inclusion is empty, then
  remove membership in any excluded custom list. Exclusion always wins,
  including overlaps and duplicates on different pages. Account-list and media
  release-status requirements remain independent; Watching alone cannot bypass
  a custom-list exclusion. This is the final rule, replacing the intermediate
  inclusion-first development checkpoint.
- **Simpler AniList settings:** all eleven account/media Import controls remain,
  while the six redundant Exclude account-status controls and their behavior are
  removed. Custom-list names use included/excluded tags with autocomplete and
  manual input. Literal commas remain part of a name. Names match exactly, with
  a unique case-insensitive fallback; ambiguous names are not guessed.
- **Preserved older list restrictions:** the duplicate legacy single-list textbox
  is hidden. Its saved name becomes an Included Custom Lists tag, preserving the
  restriction without a database migration or OAuth reset. Removing that tag
  does not restore a hidden filter. Read/Test does not rewrite stored settings;
  Save persists the normalized representation.
- **Guarded missing-membership recovery:** when AniList supplies neither a valid
  membership map nor a valid typed array and an active custom filter needs it,
  one complete collection snapshot can supply membership. It uses the same
  target/authentication, validates ownership and definitions, follows bounded
  chunk pagination and requires every sparse Page ID to be represented.
  Incomplete/error/mismatched responses retain the previous successful list.
  Existing pacing, retry limits and request-budget rules still apply.
- **Multiple remote sources:** TMDB List, Trakt List and MDBList combine selected
  source lists and subtract selected excluded lists. Use positive TMDB IDs,
  Trakt slugs/IDs or validated HTTPS MDBList URLs respectively. At least one
  included source is required. Legacy single-source settings transfer into the
  modern selection. Supported TMDB/Trakt name loading displays readable labels
  while storing the service's ID/slug; manual entry remains available.
- **MyAnimeList account lists:** the official MAL account API supports a
  registered Client ID for named public-user reads, or direct PKCE/OAuth for
  `@me` and authorized private access. Multiple official account states, minimum
  score, three airing states and exact included/excluded list tags remain
  distinct filters. Excluded tags veto overlaps. An older single-state value
  transfers into the modern selection. Jikan continues to supply public
  catalogue metadata; its retired user-list endpoint is not used for account
  imports. New/renewed MAL authorization uses the registered application rather
  than Sonarr's deliberately blocked cloud broker.
- **Jikan catalogue handling:** validates requested/returned MyAnimeList IDs,
  preserves TV/movie types and native episode numbers, skips duplicate episode
  rows and fills gaps without renumbering. HTTP 429 recovery is bounded to three
  attempts within thirty seconds with shared cooldown. Episode placeholders
  remain the fallback when catalogue details cannot be completed.
- **Optional SIMKL custom lists:** the documented read-only beta uses a separately
  registered AUTH V2 application and PRO/VIP account. Membership restricts the
  selected existing Shows/Anime Watchlist bucket, with excluded custom lists
  vetoing overlaps. V1 behavior remains when this option is unset. Incomplete,
  authentication/premium or error responses retain the prior list; movie custom
  items are ignored. Validated all-status snapshots and provider activity deltas
  reconcile native-ID deletions across restart; Test stages reads without saving
  the private snapshot or settings. No live premium-account verification is implied.
- **Complete Plex Watchlist paging:** removes the inherited silent 1,000-item
  stop. Raw offsets/sizes, optional totals and pagination headers are validated;
  short/filtered pages still advance correctly. A failed later page, inconsistent
  total or exhausted safety bound retains the previous successful list. Test
  reads the complete list without saving settings. Plex named Lists remain a
  separate capability and are not invented as Watchlist controls.
- **Provider-specific settings:** grouped account, source/tag and filter controls
  preserve unknown fields and manual input. Failed/late list-name responses do
  not discard saved selections; account changes invalidate old suggestions.
  Catalogue metadata and account-list authentication are documented separately,
  and unsupported capabilities are not presented as equivalent options.
- **Guarded pending-addition retries:** the complete-fetch witness extends from
  AniList to MAL, TMDB List, Trakt List, MDBList, Plex Watchlist and SIMKL User.
  Unchanged successful membership can resume within that provider's refresh
  interval without fetching it again. A failed fetch, changed settings, restart
  or fetched season-monitor override prevents this shortcut.

The [list configuration guide](https://github.com/KvasExpert/Tanukarr/blob/v1.0.2/docs/library-tools.md#lists-rules-and-keys)
describes selections, exclusion precedence and provider-specific limitations.
The four per-title metadata sources remain TheTVDB, TMDB, AniList and
MyAnimeList/Jikan. Jikan catalogue lookup and an authenticated MyAnimeList
account-list connection are separate operations.

## Install or upgrade

After publication completes:

```sh
docker pull ghcr.io/kvasexert/tanukarr:1.0.2
```

Take a consistent configuration backup, then change the existing Compose image
to `ghcr.io/kvasexert/tanukarr:1.0.2`, preserving the configuration mount, media
mounts, project/volume identity, ports and authentication. Run:

```sh
docker compose pull
docker compose up -d
docker compose ps
```

The [Docker installation guide](https://github.com/KvasExpert/Tanukarr/blob/v1.0.2/docs/docker-installation.md)
contains complete YAML, named-volume/bind-mount alternatives, permissions and
offline image loading. Recreate the container to apply the new image. A restart
alone retains the old image. Do not share a live `/config` between instances.

**1.0.2 is the product version.** Sonarr's core version, executable,
`config.xml`, `sonarr.db`, migration history and container port 8989 retain their
compatibility names. API v3 and v5 remain supported; API v4 is not implemented.
The release workflow targets Linux amd64; check the published architecture and
digest instead of inferring untested platform support.

The packaging workflow requires smoke, functional/security and eight additional
runtime reports for the same image. `provider-verification.json` combines those
eight reports; `release-manifest.json` records their actual check counts and
source/image identity. The configured nine assets also include the image and
corresponding source archives, SBOM, primary reports, Compose YAML and checksums.
Check the actual release assets after publication.

## Verification and limits

The new source compiled with zero warnings/errors. All 607 focused provider/Jikan
regressions, 92 frontend cases and 29 compression-worker checks passed; frontend
lint, style, types and production build also passed. The final Linux package
passed 7,485 backend cases with 27 ignored, and ten actual packaged browser
checks passed. All ten final-image runtime gates passed 176 checks. Local
deployment preserved all 35 protected tables, configuration and the owner's
292-series/one-list/292-item data; the current unsaved live AniList Test returned
HTTP 204 without saving or synchronizing. The actual
final-image scan found zero Critical advisories, three distinct High ImageSharp
advisories (21 package occurrences) and zero detected secrets; those dependencies
remain unchanged. Earlier development and 1.0.1 counts are not presented as new results;
focused subsets and repeated candidate runs are not added to the totals.

The earlier live AniList investigation observed valid public membership shapes
and successful unsaved owner Tests while the running instance had logged an
intermittent missing-membership guard. Its upstream cause was not reproduced.
Synthetic sparse responses verify the recovery design separately from a
real-account import. Service availability and rate limits remain provider
constraints; a successful connection Test does not download media or prove a
watched real-library import.

Remaining dependency findings and skipped/unavailable checks belong to the
new verification report and release artifacts. No zero-vulnerability claim or
unexecuted PostgreSQL runtime claim is made. Keep the standard ZIP backup and a
separate consistent host/database backup; backup archives can contain plaintext
credentials and do not contain media.
