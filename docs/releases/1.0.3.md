# Tanukarr 1.0.3

Tanukarr 1.0.3 improves quality-size configuration and codec-aware release size
decisions for the shared TV, anime and related-movie workflows. The four
per-title metadata sources, provider-native identities and numbering, group
membership guards, direct provider authentication and exclusion-veto list
selection remain part of the application.

The [1.0.3 publication follow-up](1.0.3-publication.md) records the published
source/image identities, verified assets, hosted checks, security findings and
deployment evidence. The [preparation ledger](1.0.3-verification.md) retains
its original candidate states; a configured workflow alone is not publication
proof. The published
[1.0.2 checkpoint](1.0.2-publication.md) retains its original evidence.

## Changes since 1.0.2

- **Readable hourly size limits.** Global Quality Definitions and profile size
  controls show MiB/hour with a GiB/hour preview. Existing API/storage values
  remain MiB/minute. Global values summarize actual profiles; mixed values are
  identified, and unchanged fields preserve differing profile settings.
- **Explicit global-save behavior.** Changed global size fields apply across
  all profiles containing the quality. Omitted API fields preserve their values,
  explicit null clears a limit, and invalid merged batches are rejected before
  writes. Full GET/PUT echoes retain nulls marked Mixed; explicit numbers still
  update. Save failures are shown with pending edits available for retry.
  Profile numeric bounds accept the same inclusive limits as the API.
- **Codec-aware decisions.** Fixed, documented codec multipliers normalize
  profile minimum/maximum checks and preferred-size ranking once. Actual
  downloaded bytes and physical indexer maximum sizes remain unchanged. The
  catalog includes AVC, HEVC, AV1, VVC and older codecs, with neutral handling
  for unknown, mixed and lossless formats. Requested factors are x262 **0.50**,
  x264 **1.00**, x265 **1.67** and AV1 **2.22**; the full policy has 15 entries.
- **Fresh upstream review.** Sonarr `develop` and all three accepted Sonarr Pro
  default heads were checked again. None had advanced beyond the recorded
  integration bases at the original checkpoint. A
  [later gaboy recheck](1.0.3-publication.md#late-upstream-recheck-and-dependency-decision)
  records three newly reviewed commits and the Release-blocked ImageSharp
  candidate without borrowing upstream validation. The useful inherited quality save-error gap is adapted
  for the current UI; an older ImageSharp branch is not imported as a downgrade.
- **English documentation cleanup.** Maintained and archived prose uses
  Tanukarr terminology. Historical versions, hashes, test counts, immutable tags
  and published asset identities remain recorded. Release pages/manifests and
  local-path placeholders identify old artifacts without inventing new names.

Read [Quality sizes and video codecs](../quality-and-codec-size.md) for the
complete factor table, examples, profile/global scope, mixed values and API
contracts. The factors are an acquisition heuristic, not measured visual
quality or a transcoding operation.

## Installation and upgrades

Use the [Docker installation guide](../docker-installation.md), the exact
versioned image and the release manifest for a verified publication. Preserve
the existing configuration mount, media mounts, Compose project/volume identity,
port and authentication. Stop the old instance and take a consistent private
backup before changing its image. A new configuration volume starts an empty
instance; a product-name change does not migrate storage.

The product release version is **1.0.3**. Sonarr's inherited core version,
assembly/executable names, `config.xml`, `sonarr.db`, migration identifiers and
supported `/api/v3` and `/api/v5` paths are independent compatibility identifiers.
The size-editor unit change does not authorize converting stored API values to
hourly units. The optional compression worker remains separate.
